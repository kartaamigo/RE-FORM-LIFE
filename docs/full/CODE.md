# Техническое устройство

## Стек

| Слой | Реализация |
| --- | --- |
| Сервер и шаблоны | Python, Flask 3.1.3, Jinja |
| Хранение | SQLite через стандартный `sqlite3` |
| Интерфейс | HTML, CSS, обычный JavaScript |
| Desktop | pywebview 6.2.1 |
| Упаковка | PyInstaller 6.22.3, Windows/macOS spec |
| Локальная речь | Vosk 0.3.45, sounddevice 0.5.6 |
| Разговорная модель | Gemini REST `generateContent` через urllib |
| Голосовые профили | Silero V5 либо Qwen3-TTS |
| Облачная речь | Дополнительный Yandex SpeechKit |

В проекте нет обязательного npm-сборщика интерфейса. Node используется для проверки синтаксиса JS. Версии дополнительных пакетов — в requirements-файлах; верхние зависимости частично заданы диапазонами, поэтому их набор не является полным lockfile.

## Запуск и потоки данных

`launcher.py` выбирает `REFORM_LIFE_PORT` либо свободный порт, поднимает Flask на `127.0.0.1`, ждёт доступность и открывает pywebview. Окно: 1400 × 900, минимум 1200 × 700. Голосовая модель загружается после события `window.events.loaded`, чтобы не задерживать появление страницы.

Обычная операция: UI → fetch JSON API → валидация → SQLite → JSON → обновление UI. HTML-страницы рендерит Jinja. Модельные запросы дополнительно проходят ограниченный инструментальный цикл; действия ОС выполняются адаптером приложения.

Путь обработки EVE:
1. Вход через API команды; проверка текста/источника и голосового имени.
2. Выбор распознанного варианта и подавление повторной голосовой команды.
3. Разрешение пользовательской фразы.
4. Режим prompt → Gemini harness; режим command → локальный разбор.
5. Поддерживаемый intent → обработчик приложения или ОС.
6. Неизвестная/неоднозначная команда → доступный модельный сценарий либо объяснение ограничения.
7. Ответ и сохранение истории.

Отдельный `/api/assistant/chat` запускает модельные инструменты чтения с `allow_changes=False`. Единый UI команд не делает эти два серверных маршрута одинаковыми.

## База и миграции

Основные таблицы: задачи/разделы, цель недели/заметки/приоритеты, операции/накопления, коммунальные счета/услуги/платежи/показания, привычки/отметки/настроение, настройки/истории/память EVE. Harness добавляет `assistant_task_proposals`, редактор — `assistant_commands`.

`get_db()` создаёт соединение в контексте Flask, включает foreign keys, `synchronous=FULL`, ожидание занятой базы и выполняет схему/совместимость старых колонок. Соединение закрывается по завершении контекста. Это собственный механизм инициализации, а не нумерованный внешний migration framework.

Деньги хранятся целыми `amount_minor`. Для показаний используется REAL. Ограничения CHECK, UNIQUE, FK, индексы и их точные поля — в [DATABASE](DATABASE.md). Не следует определять денежную точность по форматированию числа на экране.

## API и валидация

В `app.py` есть отдельные проверки текста, даты, месяца, времени, денег, прогресса, настроения, цвета, расписания и назначения задачи. SQL-запросы в обычных сценариях используют параметры; в harness динамические имена изменяемых полей проходят разрешённый набор.

Список страниц и всех явно зарегистрированных маршрутов — [API](API.md). Это статический реестр, без обещания полного OpenAPI-контракта. Для конкретного тела запроса источником служит обработчик и существующий тест.

Например `POST /api/assistant/command` принимает `text`, `source`, опционально `alternatives`; для `local_voice`/`browser_voice` применяется голосовая активация. У модели нет доступа к SQL или терминалу по произвольному тексту.

## Действия ОС и интеграции

`eve_agent.py` содержит поддержку открытия браузера/URL, приложений и проводника, файловых операций, громкости, яркости, Wi-Fi, активного окна и питания с платформенными ветками. `app.py` добавляет получение погоды и подтверждаемые скачивания/запуск установщика. Наличие ветки кода для Windows/macOS не доказывает её работоспособность на каждом устройстве.

Встроенные команды ОС и пакеты задач ИИ имеют разные хранилища подтверждений. Старые ожидающие действия ОС хранятся в словаре процесса; модельные пакеты задач — в SQLite. Подтверждение может прийти кнопкой API либо предусмотренной фразой.

## Технические ограничения для следующего этапа

- Локальный API не имеет полноценной пользовательской аутентификации. Границы Host/Origin и изменяющих запросов требуют отдельной проверки.
- `app.py`, `app.js`, CSS объединяют много областей; постепенное разделение облегчило бы поддержку.
- Инициализация схемы и legacy-полей выполняется в ходе подключения; нужны контролируемые миграции и резервное копирование.
- Один процесс блокирует параллельные модельные запросы через lock; это не распределённая многопользовательская очередь.
- Множество CSS-переопределений осложняет определение конечного стиля.
- Пределы проверки реального звука, моделей и сборок — в [EVIDENCE](EVIDENCE.md).

Эти пункты — наблюдения по исходникам, не новый полноценный аудит безопасности.
