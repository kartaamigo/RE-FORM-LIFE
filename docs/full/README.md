# Полный комплект документации RE:FORM LIFE

Дата сбора: **14 октября 2026 года**. Зафиксированный снимок приложения: **`299d311`**. Источники: отслеживаемые файлы, исходники и вся локально доступная история Git от `b8d0032` (25 сентября 2026 года). Документация описывает этот снимок; коммит самой документации появляется после него.

Это собрание технической, продуктовой и дизайнерской информации. Оно различает реализацию, историческую замену, сохранённый референс и будущую рекомендацию. Название коммита не доказывает успешный релиз, а наличие адаптера модели не доказывает установленную модель.

## Что читать сначала

Для общего знакомства — PRODUCT и CHANGES. Для разработчика — CODE, AI, API и DATABASE. Для дизайнера — DESIGN и ASSETS. Для запуска и передачи проекта — OPERATIONS и EVIDENCE.

Ранее созданные материалы сохранены в [общем каталоге](../README.md). [HARNESS](../HARNESS.md), [команды EVE](../EVE_COMMANDS.md) и [исследование Luxify](../EVE_LUXIFY_REFERENCE.md) содержат дополнительные подробности этапа 10 октября. Отчёты от 1 октября следует читать как описание того этапа, а актуальные различия — здесь.

## Правила дальнейшего ведения

При новом изменении фиксировать: проблему, поведение до/после, пути, коммит, способ проверки и оставшиеся ограничения. Для дизайна дополнительно указывать область действия CSS, заменённый элемент, сохранённые исходные ресурсы и актуальные состояния. Для ИИ — провайдера, идентификатор модели, инструменты, передаваемые данные и границы исполнения.

Если изменение удаляет элемент из шаблона, но оставляет SVG/CSS в Git, записывать именно замену использования. Если функциональность только обсуждалась, помещать её в планы, а не в список внедрений. Для следующего снимка обновлять реестры API, схемы, символов, настроек и хешей.
