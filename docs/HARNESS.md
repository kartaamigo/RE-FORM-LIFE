# Agent harness и OpenClaw

Дата фиксации: **10 октября 2026 года**.

## Решение и границы работы

Сначала разбираем OpenClaw как agent harness: архитектуру, цикл выполнения,
контекст, память, инструменты, права и варианты интеграции. Установка и изменение
поведения EVE пока не выполняются. Выбор OpenClaw для продукта не утверждён.

Ниже отделены сведения из официальной документации от предложений для
RE:FORM LIFE. Документация ветки `main` меняется; перед установкой нужно сверить
возможности и требования с выбранным релизом.

## Что такое harness

Agent harness — программная среда вокруг модели, которая собирает контекст,
исполняет разрешённые вызовы инструментов, возвращает результаты модели,
сохраняет состояние и управляет продолжением или завершением задачи.

Типичный цикл:

```text
Запрос пользователя
  → сбор контекста и доступных инструментов
  → вызов модели
  → проверка и выполнение запрошенных инструментов
  → результаты инструментов в контекст
  → следующий вызов модели или завершение
```

Модель предлагает действия; harness исполняет их по правилам приложения.
Текстовая инструкция сама по себе не обеспечивает ограничение доступа.
Обычный чат с моделью может состоять из одного запроса и ответа. Для агента
нужны также обработка действий, состояние и контроль выполнения.

| Слой | Ответственность |
| --- | --- |
| Модель | Понимание запроса, выбор следующего действия, формирование ответа |
| Harness | Контекст, цикл вызовов, инструменты, лимиты, отмена и сохранение состояния |
| Инструмент | Конкретная исполняемая операция с проверяемым входом и результатом |
| Skill | Инструкции и ресурсы для способа выполнения работы; сам по себе не выдаёт права |
| Приложение | Данные, предметные правила, интерфейс и окончательная проверка операций |

## Что проверено про OpenClaw

- Gateway соединяет сессии, интерфейсы, инструменты, события и каналы общения.
- Встроенный runtime собирает prompt и управляет циклом модели и инструментов.
  Документация также описывает делегирование внешним harness; возможности
  конкретного runtime нужно проверять отдельно.
- Bootstrap-контекст включает `AGENTS.md`, `SOUL.md`, `IDENTITY.md`, `USER.md`
  и другие файлы workspace. Большие файлы могут обрезаться при загрузке.
- Долгосрочная память хранится в `MEMORY.md`, рабочие заметки — в `memory/`.
  Память не равна полной истории диалога и не гарантирует безошибочное извлечение.
- История сессий хранится отдельно. Compaction сокращает старую историю до
  резюме для следующих запросов модели, сохраняя полную историю на диске.
- Плагины добавляют исполняемые возможности; skills задают способы работы.
- Запуски сериализуются внутри сессии; предусмотрены очереди, поток событий,
  ожидание результата и таймауты.
- Sandbox по умолчанию выключен. Политику инструментов и изоляцию необходимо
  настраивать явно; Gateway остаётся на хосте.
- Совместимый endpoint `/v1/chat/completions` выключен по умолчанию.
  Gateway-токен для него даёт широкие операторские полномочия.
- Прочитанная документация требует Node 24.16+ или 26.1+ и рекомендует Node 26.
  Windows поддерживается через Hub, native CLI/Gateway и WSL2.

## Связь с текущей EVE

По исходникам проекта EVE уже имеет разбор команд, историю, память,
подтверждение некоторых действий и разговор через Gemini. Это отдельные
составляющие агентной среды; наличие общего многошагового цикла выполнения
произвольных задач пока не подтверждено этим исследованием.

Предлагаемая, ещё не реализованная схема интеграции:

```text
Интерфейс и голос EVE → OpenClaw → инструменты RE:FORM LIFE → Flask → SQLite
```

Flask должен сохранять владение данными и предметными проверками. Агенту
предлагается дать узкие операции приложения вместо прямого редактирования базы.
Gateway-токен должен храниться в backend, а не в браузерном JavaScript.
Потребуется определить владельца истории и памяти, чтобы не получить две
независимые версии состояния в EVE и OpenClaw.

## Порядок дальнейшего разбора

1. Проследить один запрос от входа до результата и определить критерий завершения.
2. Разобрать сбор контекста, лимиты, compaction и поиск в памяти.
3. Разделить инструкции skills и исполняемые инструменты plugins.
4. Разобрать права, подтверждения, отмену, таймауты и ошибки инструментов.
5. Сравнить готовый OpenClaw с небольшим harness внутри Python-приложения.

Предложение для будущего прототипа: отдельный workspace EVE и один инструмент
чтения задач для запроса «Что у меня сегодня?». Затем — создание задачи с
проверкой сохранения. Установка, выбор модели, расходы, аутентификация между
компонентами и окончательный контракт инструментов ещё не определены.

При первичной проверке окружения найден Node 24.19.0; `npm` и `openclaw` не
найдены в PATH. Это результат проверки PATH, а не доказательство их отсутствия
на компьютере. OpenClaw не установлен в рамках этой работы и не запускался.
