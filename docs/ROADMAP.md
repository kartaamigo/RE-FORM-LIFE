# План развития

Это предлагаемый порядок работ без обещанных дат. Новые идеи отделены от существующих возможностей.

## 1. Стабильность личного прототипа

- Резервные копии и восстановление с проверкой формата.
- Проверка доступа к локальному API, запросов изменения данных и подтверждений EVE.
- Надёжный запуск без debug, понятные ошибки отсутствующих моделей и микрофона.
- Тесты сохранения после перезапуска и миграции старой базы.

**Готовность:** данные можно восстановить, приложение понятно сообщает о сбоях, важные сценарии проходят повторяемые проверки.

## 2. Единый продукт и дизайн

- Закрепить название, роль EVE и персонажа.
- Собрать единые токены цветов, размеров, отступов и состояний.
- Убрать несогласованные числа из демонстрационных материалов.
- Проверить фокус, клавиатуру, контраст и небольшие окна.
- Снять скриншоты текущей реализации на демонстрационных данных.

**Готовность:** человек понимает текущий раздел, может выполнить основные действия с клавиатуры и отличает готовый интерфейс от концепта.

## 3. Поддерживаемая архитектура

- Разделить сервер по предметным областям и ввести версионные миграции.
- Разделить JavaScript и убрать дублирование CSS.
- Добавить автоматический запуск тестов для обычных изменений.
- Проверить чистую установку и сборки на отдельных компьютерах.

**Готовность:** изменение одного раздела проверяется независимо, а новый разработчик может запустить проект по документации.

## 4. Проверка новых идей

| Идея | Польза | Как проверить |
| --- | --- | --- |
| Обзор «Мой день» | Быстрее выбрать главное | Пользователь находит следующее действие без объяснений |
| Недельный итог | Осмысленно перенести дела и учесть отдых | Пользователь составляет реалистичный следующий план |
| Шаблоны рутин | Меньше повторного ввода | Сравнить число действий при создании типовой недели |
| Прозрачные режимы EVE | Понимание микрофона, облака и памяти | Пользователь может объяснить, куда отправляется его сообщение |
| Связь цели и задачи | Превратить намерение в шаг | Пользователь создаёт конкретную задачу из цели |

Синхронизацию, мобильную версию и командные функции стоит обсуждать после проверки основного личного сценария: они заметно увеличивают сложность хранения, доступа и поддержки.

## Перед переходом в публичный репозиторий

Сейчас доступ остаётся закрытым. Открытие — отдельное последующее действие по решению владельца.

1. Проверить содержимое и историю Git на ключи, личные данные и записи. Обнаруженные ключи отозвать; одного удаления из последнего коммита недостаточно.
2. Выбрать лицензию исходников и явно описать права на фирменную графику.
3. Проверить разрешения на распространение каждого шрифта и сторонней модели; при необходимости заменить ресурсы.
4. Уточнить лицензии Vosk, personal/commercial TTS и комплектуемых компонентов в едином реестре.
5. Получить обезличенные скриншоты работающей версии и отдельно оставить концепты.
6. Проверить установку, тесты и скачиваемые сборки на чистом окружении.
7. Добавить правила участия, сообщения об ошибках и поддерживаемые платформы.
8. После этого согласовать момент открытия и публикации анонса.

## Как представить проект

Начать с проблемы: планы, деньги и бытовые дела разбросаны. Затем показать короткий сценарий: открыть день, добавить задачу, отметить результат. Завершить ролью EVE и честным статусом ранней версии.

Для будущего анонса можно подготовить короткое видео, три реальных скриншота, историю создания и список ближайших улучшений. Оценивать отклик лучше по обратной связи и повторному использованию, чем только по просмотрам. Публикация анонсов и сообщений в рамках этого оформления не выполнялась.
